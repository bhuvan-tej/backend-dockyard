# 08 · Lombok

> Lombok generates boilerplate (getters, constructors, builders…) **at compile time**
> from annotations, so your classes stay short. The generated code is real bytecode —
> it just isn't in your source file.

---

## 🍬 The annotations used in this repo

| Annotation | Generates | Typical use |
|-----------|-----------|-------------|
| `@Getter` / `@Setter` | getters / setters (class or field level) | entities, DTOs |
| `@Data` | getters + setters + `toString` + `equals` + `hashCode` + required-args ctor | DTOs, value objects |
| `@Builder` | fluent builder pattern | constructing objects readably |
| `@NoArgsConstructor` | empty constructor | **JPA entities need this** |
| `@AllArgsConstructor` | constructor with all fields | with `@Builder` |
| `@RequiredArgsConstructor` | constructor for `final` fields | **constructor injection** |
| `@Slf4j` | a `private static final Logger log` | logging |

---

## 💉 `@RequiredArgsConstructor` — the DI workhorse

This is the most important one in a Spring app. It generates a constructor for every
`final` field, giving you **constructor injection with zero boilerplate**:

```java
@Service
@RequiredArgsConstructor
public class ProductService {
    private final ProductRepository repository;   // ← included in generated ctor
    private final Mapper mapper;                   // ← included too
}
```
Lombok writes: `public ProductService(ProductRepository repository, Mapper mapper) {...}`
and Spring uses it to inject both dependencies.

## 🏗️ `@Builder` — readable object creation

```java
@Builder
public class Product {
    private String name;
    private BigDecimal price;
    private int stock;
}

Product p = Product.builder()
        .name("Pen")
        .price(new BigDecimal("9.99"))
        .stock(100)
        .build();
```
Great for objects with many fields — no guessing constructor argument order.
Usually paired with `@AllArgsConstructor` (the builder needs an all-args ctor).

---

## 📦 `@Data` — the everything bundle

```java
@Data                        // getters + setters + toString + equals + hashCode + RequiredArgsCtor
public class ProductRequest {
    private String name;
    private BigDecimal price;
}
```
Perfect for **DTOs**. ⚠️ **Avoid on JPA entities** — see gotchas.

---

## 📝 `@Slf4j` — instant logging

```java
@Service
@Slf4j
public class OtpService {
    public void send(String phone) {
        log.info("Sending OTP to {}", phone);      // 'log' generated by Lombok
        log.debug("Full request context: {}", ctx);
    }
}
```
No need to declare `LoggerFactory.getLogger(...)` yourself.

## ⚠️ Gotchas & best practices

1. **Don't use `@Data` on entities.**
   - Its `toString()` can traverse lazy relations → `LazyInitializationException` or
     infinite recursion.
   - Its `equals()/hashCode()` use all fields → breaks JPA identity semantics.
   - ✅ Use `@Getter @Setter @NoArgsConstructor` and, if needed, an `equals/hashCode`
     based only on the `@Id`.

2. **Entities need `@NoArgsConstructor`** — JPA/Hibernate instantiate via reflection.

3. **Records vs Lombok** — Java `record`s already give you immutability, getters,
   `equals/hashCode/toString`. Prefer records for simple immutable DTOs; use Lombok when
   you need mutability or builders.

4. **IDE support** — install the Lombok plugin so the IDE "sees" the generated methods.

5. **It's compile-time only** — no runtime reflection cost, no runtime dependency issues.

## 🔁 Before vs after

```java
// Without Lombok — 40+ lines
public class Product {
    private Long id; private String name;
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    // + equals, hashCode, toString, constructors...
}

// With Lombok — 4 lines
@Getter @Setter @NoArgsConstructor @AllArgsConstructor
public class Product {
    private Long id;
    private String name;
}
```
